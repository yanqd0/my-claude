根据当前对话上下文中涉及的修改，执行 git commit。可接收一个可选参数 `<split_plan>`，描述如何将改动拆分为多次提交。

## 执行步骤

1. 运行 `git status` 和 `git diff`（含 `--staged`）确认变更范围。
2. 确定提交方案：
   - **无 `<split_plan>`**：所有修改合为 1 次提交，跳到步骤 4。
   - **有 `<split_plan>`**：从中解析出本次共几个提交、每个提交的意图和对应的文件/改动。若描述中未明确提交次数或各次内容，向用户提问确认后再继续。
3. 多 commit 拆分（仅当有 `<split_plan>` 时）：按描述的顺序，逐次 `git add` 相关文件只做那一次提交的修改，执行 `git commit`，再继续下一次提交，直到全部完成。
4. 每次 `git commit` 的提交信息均按下方的格式规范撰写。

## 提交信息格式

```
<title>

<description>
```

- **title**：言简意赅，≤40 字符，中文。
- 标题后空一行，再接 description。
- **description**：详细说明改动内容，中文，Markdown 格式。代码符号、文件名不翻译。
- 不加 co-author、generated by 之类信息。
