根据功能描述在当前项目创建一个项目级 agent。支持两个参数：`<description>` 必选，`<name>` 可选。

## 执行步骤

1. **解析参数**：`<description>` 为 agent 职责描述；`<name>` 为名称（小写字母+连字符），缺省待步骤 3 推断确认。
2. **学习与角色匹配**：`Read` `references/role-index.md`；`Glob` 列出 `~/.claude/agents/*.md`
   与 `./.claude/agents/*.md` 既有 agent。将 `<description>` 与角色索引表匹配：
   - 命中角色 → 记为候选模板；
   - 未命中 → 走 role-index 中的通用骨架；
   - `<name>` 与全局 agent 同名 → 覆盖场景（nearest wins），读取被覆盖者以对齐职责边界、写明差异。
3. **name 处理与前置确认**（可多轮，后续步骤不再确认）。
   首轮固定：**路径/name 第一，总体评审最后**，中间为审视发现的问题。首轮后 name 与总体
   评审已定案，后续轮次 4 个位置全部交给审视问题。

   审视问题的密度不设上限——description 不清晰恰恰说明用户需要专业引导来梳理想法。
   单轮装不下则主动进入下一轮，直至所有必要信息齐备。每轮题序自行组织，同类合并。

   每轮 `AskUserQuestion` 最多 4 题（工具上限）。首轮：路径/name 与总体评审各占 1 题，
   审视问题占 2 题——超过 2 个审视问题即进入第二轮。
   后续轮次 4 题全给审视，直至无新问题。

   审视维度：触发场景明确度、职责边界（负向排除）、是否需要写权限、与既有 agent 有无重叠、
   角色模板候选是否采用。

   总体评审（仅首轮最后一题）：综合给出建议结论——
   - 职能合适性：该做 agent，还是更该用 hook（确定性检查）/skill（流程知识）/CLAUDE.md
     一行（简单事实）？参照 `.claude/rules/agent-structure.md` 的分层判断。
   - 项目需求度：项目复杂度与生命周期值得配常驻角色吗（孤立脚本、短命项目不值得）。
   - 成本收益：预估触发频率 × 每次 token/时间成本，是否小于收益；高频低价值建议降级。
   - 选项：推荐结论置首（如"评审通过，按此创建"），另有"调整后创建（在 Other 描述）"、
     "改用其他机制（hook/规则），本次不建"。
4. **生成内容**：角色命中**且用户在步骤 3 未拒绝该候选** → `Read` `references/roles/<role>.md`，
   按模板填充 `<项目专有知识>` 占位（优先从代码库探测：构建文件、CI 配置、目录结构；
   探测不到的已在步骤 3 向用户确认）；未命中或用户拒绝候选 → 按通用骨架生成。
5. **写入与收尾**：写入步骤 3 确认的路径；若 `.claude/agents/` 目录为本次新建，
   提醒需重启 Claude Code 会话才会加载；建议将该文件纳入版本控制。
