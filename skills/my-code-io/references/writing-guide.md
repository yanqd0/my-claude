# 撰写规范

## 大纲规划（步骤 3）

- 标题层级最多 5 层（`#####`）。
- 内容排序：业务优先于技术，架构优先于细节；关键的技术细节可提前着重写。根据实际重要程度调整章节顺序。
- 章节取舍：不重要或内容不足的章节直接省略，不填充冗余内容。
- 超 300 行时提示用户：合并为一篇、或拆分为多篇。

## 多篇拆分（步骤 7）

- 每篇聚焦一个主题（如"架构概述"、"核心流程"、"数据与存储"）。
- 每篇开头列出系列中其他文章的链接。
- 每篇单独确认大纲后再撰写保存。

## 语言与读者

- 中文为主，代码符号、类名、函数名、关键概念保留英文原文。严谨准确，避免口语化。
- 读者具备基本技术常识，但不了解项目技术栈和业务背景。开篇先解释"这个项目是干什么的"。
- 说明"为什么"而非仅"是什么"：解释设计意图、业务背景。

## 代码引用

- 关键代码片段不超过 25 行，用 Markdown 代码块并标注语言。
- 引用前加一句解释该代码做了什么。
- 标注文件出处（项目根目录的相对路径）。
- 避免大段粘贴，优先简洁描述 + 短小关键片段。
- 源码无注释时可在代码块内添加注释；已有丰富注释则不修改，改为正文补充说明。
- 某模块预计超 80 行章节时，提示拆分为独立文章。

## 图表（步骤 5）

对每个需要可视化的内容，使用 `Skill` 工具调用 `my-mermaid`，传入绘图内容描述。my-mermaid 返回带配色的代码，直接嵌入。

### 图类型路由

`Read` `~/.claude/skills/my-mermaid/references/type-index.md` 获取图类型选择表（单一事实来源）。根据文章内容在表中匹配对应的 mermaid 图类型。常见映射：

| 文章内容 | 图类型 |
|---------|--------|
| 整体架构、分层结构 | `flowchart TB` |
| 模块依赖、组件关系 | `flowchart LR` |
| API 调用链、请求流程 | `sequenceDiagram` |
| 状态变更、生命周期 | `stateDiagram-v2` |
| 类/接口层次 | `classDiagram` |
| 数据库表关系 | `erDiagram` |
| 项目演进、版本历史 | `timeline` |
| 功能占比、构成分析 | `pie` |
| 性能对比 | `xychart` |
| 分支策略 | `gitGraph` |
| 项目目录、知识体系 | `mindmap` |
| 根因分析、方案对比 | `ishikawa-beta` |

不适合 mermaid 的内容（目录树、对照表等）用 ASCII 替代。每张图前用文字说明内容和如何阅读。
